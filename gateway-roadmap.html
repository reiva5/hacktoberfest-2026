One gateway to ASEAN startup programs and funding

For founders, the hard part isn't finding a list of programs. It's working out which of the hundreds spread across ten countries they actually qualify for before the deadline. We start by aggregating so the gateway is useful on day one, then move organisations onto direct listings.

Aggregate institutions./Invite people.

Phases

What we build now, next, and later

MVP

Eligibility-matched programs

Hackathon · today

Programs and funding calls, crawled from 15–20 seed sources and pulled into structured records by Gemma. A founder uploads a pitch deck and gets matched programs. Startup ASEAN sees a map of where the region lacks support.

Next phase

Pilot with Startup ASEAN

~3 months after

Automatic discovery of new sources, accounts and deadline alerts, and organisers claiming their own listings. Funders and investors added as the second category.

Later

The full gateway

6–12 months

Opt-in talent profiles, partner matching, and an ecosystem data layer for governments and ecosystem builders.

Data model

The program record

Gemma fills this record for every page. Matching depends on the eligibility fields, so they are the most important part.

program {
  title, organiser, organiser_url
  type:         accelerator | grant | competition | gov_scheme | credits
  countries:    [ISO codes]          # where applicants must be based
  sectors:      [..]                 # empty = sector-agnostic
  stages:       idea | pre-seed | seed | series-a+
  funding:      { amount, currency, equity_free: bool, equity_pct }
  eligibility:  [free-text rules]    # shown as "why you qualify"
  deadline:     date | rolling
  language:     original page language
  canonical_url, seen_on: [aggregator urls]
  last_verified, extraction_confidence
}

Today

Who builds what

Person A · pipeline
  • Seed list: MYStartup or Startup SG, Cradle, Google for Startups SEA, Antler, e27 or Devpost, plus one non-English page
  • Fetch → clean → Gemma extraction → validation
  • Follow aggregator listings back to the organiser's page and remove duplicates
  • "Paste a URL" endpoint for the live demo
  • Deck → profile: slides as images into Gemma, with plain PDF text as a fallback
Person B · product
  • Profile form and matching logic (eligibility filter, then rank)
  • Match cards with the reason they fit, the deadline, and the source
  • Run the pipeline ahead of time and cache 30–50 records so the demo works offline
  • Gap map view: country × stage grid with empty cells highlighted
  • Pull the four pitch numbers from the database
  • Pitch: the problem, the live demo, and how it grows into the full gateway

If time runs short, cut the deck upload before the gap map. The gap map is cheaper and speaks to the sponsor.

Demo script · about 4 minutes

  1. Open with the pitch numbers"We found ___ programs; ___ aren't on any aggregator"
  2. Drop in a founder's pitch deckProfile fills itself, matches appear with reasons and deadlines (the founder moment)
  3. Paste a Bahasa Indonesia program pageComes out as an English structured record in about 20 seconds
  4. Show the gap map"Here's what the region is missing" (the sponsor moment)
  5. 20 seconds: restyle a source page liveExtraction still works, so the crawler survives redesigns
  6. Close on the next-phase slideOrganisers claim their listings; talent profiles are opt-in

Deliberately left out of the MVP

  • LinkedIn or other talent scraping. Against LinkedIn's terms, a PDPA risk, and a bad look for a public body. Talent will be opt-in later.
  • Logins and accounts. They add nothing for judges watching a 4-minute demo.
  • Partners category. Too vague to demo well.
  • Funder database. Moved to the next phase. Good open data on funders is hard to find.
  • Large-scale discovery. Show that it works on the seeds rather than claiming coverage.

Risks to plan around

  • Gemma 4B gets eligibility fields wrong. Use 12B/27B for extraction and 4B only to classify pages.
  • Live inference is slow on stage. Cache everything except the paste-a-URL moment.
  • Out-of-date listings lose trust fast. Show "verified on" and the source on every card.
  • Sites block the crawler. Crawl politely, respect robots.txt, and prefer each organiser's own page.
  • Gemma misreads a design-heavy deck. Show which slide each field came from, keep every field editable, and test on two or three real decks beforehand.
  • The gap map overstates gaps. With only 15–20 sources, an empty cell may just mean we haven't crawled there yet. Label it "coverage so far".
